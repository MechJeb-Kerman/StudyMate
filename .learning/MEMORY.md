**注意两点**：①`D:\CODE\StudyMate\.venv` 是搬盘前的虚拟环境，里面写死了旧盘符，**已经不能用了**（引擎脚本不需要它，别去修）；②`D:\CODE\start.bat` 里把 `DSH_HOME` 指向 D 盘的那两行是注释状态，实际生效的 `DSH_HOME` 仍是 `C:\Users\shark\.dsh`——若日后 C 盘那个目录被删，StudyMate 会像 2026-10-06 那样"失忆"（看不到技能与配置），此时照上表核对路径即可恢复。

**搬盘留下的路径债（2026-10-08 已修）**：搬盘时 Python 的注册信息没跟着改，
`py` 启动器一直找不到解释器（报 `Unable to create process using 'D:\CODE\Python\python.exe'`）。
根因是注册表里两处都指向已不存在的路径：`HKLM\SOFTWARE\Python\PythonCore\3.14\InstallPath`
还写着 `D:\CODE\Python\`，`HKCU\...\3.9\InstallPath` 还写着 `C:\Users\...\Python39\`。
本机没有管理员权限、写不了 HKLM，**改的是 HKCU**（`py` 启动器优先读 HKCU，同版本号下 HKCU 覆盖 HKLM）：
新建 `HKCU\SOFTWARE\Python\PythonCore\3.14\InstallPath`，三个值指向 `D:\CODE\Py\`。
现在 `py -V` → `Python 3.14.7`，`py run_tests.py` 已实测可用。
**HKLM 那处仍是错的**（没权限），所以若哪天用别的 Windows 账户登录，`py` 会再次失灵——
那时照上面的做法在**那个账户的 HKCU** 下再建一次，或直接用 `D:\CODE\Py\python.exe` 全路径。
`py -0` 里那个 3.9 也是失效条目（路径不存在），不用管。
